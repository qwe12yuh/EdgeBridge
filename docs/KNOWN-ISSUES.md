# 已知问题与路线

当前版本为开发者预览。普通 PPT 的双向手动拖放已通过，详细证据见 [验证记录](../VALIDATION.md)。

- **Windows 迟到回执与两阶段释放**：OLE 目标处理可能超过 2 秒；此前实机回拖中原生最终返回 DROP + COPY，但协调器因 2 秒等待窗口先记录了 `cancelled`（用户已确认该次实际回拖落盘成功）。现已在 `GestureLab.cs` 与 `SourceGesture` 中拆分“OLE 消费物理松手（`drop-released`，立即向路由器发送 `finish` 释放点击隔离）”与“目标应用完成复制（`finishTimeout` + `late-result` 迟到回执记录）”，并通过单测与原生自检；仍待下一次双机慢目标实机复测确认后再从已知问题移除。
- **完整暂存与 64MiB 限制**：目前没有跨机文件承诺/虚拟流，大文件不能在传完前完成交接；暂存须在路由器约 5 秒的准备窗口内完成（默认 4500ms），手势上传现为边传边校验，不再读两遍文件。
- **部署尚需手动完成**：双端构建、TLS 配对、SSH 隧道、Deskflow 外部适配器和 macOS 辅助功能授权。没有安装器、自动发现、正式签名或开机自启。
- **更多交互待验收**：多文件/目录拖放、快速移动并松手、不同目标应用、Esc、断线、休眠与重连。

发布包只提供源码；不含已签名的安装程序、配对凭证或正在运行机器的配置。旧 `bridge.mjs` 是早期实验，不应与 `gesture-lab.mjs` 同时运行。
